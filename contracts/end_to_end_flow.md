# AIPrep End-to-End System Flow

As-is flow : *"Start from, see, UI to API, API to orchestrator, then orchestrator to engine, engine to something. So give me all that as a flow."*

This document traces the exact path of data as it moves through the entire system during the evaluation phase, explicitly naming **which engine** is being used at every step based on the Core Engine diagram.

---

### Step 1: UI to API (Create Assessment)
**Action:** The candidate selects an assessment type and clicks "Start". The UI calls `POST /assessments`.
**Payload Transmitted:**
```json
{
  "candidate_id": 1001,
  "assessment_type": "TECHNICAL",
  "media_type": "VIDEO"
}
```

---

### Step 2: API to DB (Initialize Session)
**Action:** The API inserts a new row into `ai_prep_assessment` with status `IN_PROGRESS` and returns the `assessment_id` to the UI.

---

### Step 3: UI to API (Submit Telemetry)
**Action:** The candidate finishes the recording. The frontend React app submits the captured metrics to the FastAPI backend via `POST /assessments/{id}/data`.
**Payload Transmitted:**
```json
{
  "questions": [ { "question_id": 101, "question_text": "Explain RAG." } ],
  "transcript": { "full_text": "...", "segments": [] },
  "audio_telemetry": { "words_per_minute": 135, "silence_ratio_pct": 12.5 },
  "video_telemetry": { "face_visible_pct": 98.5, "head_nods_count": 12 }
}
```

---

### Step 4: API to DB (Save Telemetry)
**Action:** The API saves the received payload into the `ai_prep_assessment_data` table.

---

### Step 5: UI to API (Trigger Evaluation)
**Action:** The UI calls `POST /assessments/{id}/evaluate` to kick off the grading process. The API changes the status to `EVALUATING`.

---

### Step 6: API to Orchestrator (Start Background Job)
**Action:** The API triggers the background assessment orchestrator to begin processing the evaluation.
**Payload Transmitted:**
```json
{ "assessment_id": 12345 }
```

---

### Step 7: Orchestrator to DB
**Action:** The Orchestrator queries the database to load the entire assessment context into memory.
**Data Retrieved:** Assessment Type, Questions, Transcript, Audio Telemetry, Video Telemetry.

---

### Step 8: Orchestrator to Audio Engine
**Action:** Orchestrator asks the **Audio Engine** to process the raw audio telemetry.
**Payload In:** `{ "words_per_minute": 135, "silence_ratio_pct": 12.5 }`
**Payload Out:** `{ "audio_context": "Candidate spoke at 135 WPM..." }`

---

### Step 9: Orchestrator to Video Processor Engine
**Action:** Orchestrator asks the **Video Processor Engine** to process the raw video telemetry.
**Payload In:** `{ "face_visible_pct": 98.5, "head_nods_count": 12 }`
**Payload Out:** `{ "video_context": "Face was visible 98.5% of the time..." }`

---

### Step 10: Orchestrator to Assessment Engine
**Action:** Orchestrator asks the **Assessment Engine** to format the Q&A text and rubrics.
**Payload In:** `{ "assessment_type": "TECHNICAL", "questions": [...], "transcript": {...} }`
**Payload Out:** `{ "qa_context": "Q: Explain RAG. A: RAG stands for..." }`

---

### Step 11: Orchestrator to Eval Engine
**Action:** Orchestrator passes all the generated contexts from Steps 8, 9, and 10 into the **Eval Engine** to construct the final LLM prompt.
**Payload In:**
```json
{
  "audio_context": "...",
  "video_context": "...",
  "qa_context": "..."
}
```
**Payload Out:**
```json
{
  "system_prompt": "You are an expert AI coach...",
  "user_prompt": "Evaluate this transcript...",
  "response_format": "json_object"
}
```

---

### Step 12: Orchestrator to LLM
**Action:** The Orchestrator executes the network call to the LLM (OpenAI/Gemini).
**Payload In:** The prompts generated by the Eval Engine in Step 11.
**Payload Out:** A raw, unverified string containing the LLM's JSON response.

---

### Step 13: Orchestrator to Scores Engine
**Action:** The LLM's raw string cannot be trusted blindly. The Orchestrator passes it to the **Scores Engine** for strict parsing and schema validation.
**Payload In:** `{ "raw_json_string": "{\"audio_evaluation\": {...}, ...}" }`
**Payload Out:**
```json
{
  "is_valid": true,
  "parsed_report": {
    "audio_evaluation": { "coherence": { "score": 85, "feedback": "Good" } },
    "video_evaluation": { "professional_presence": { "score": 90, "feedback": "Good" } },
    "transcript_evaluation": { "technical_accuracy": { "score": 85, "feedback": "Accurate" } }
  }
}
```

---

### Step 14: Orchestrator to DB
**Action:** The Orchestrator takes the validated `parsed_report` from the Scores Engine and saves it directly into the `ai_prep_assessment_report` table, then marks the assessment status as `COMPLETED`.
